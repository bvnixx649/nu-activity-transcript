# การตัดสินใจ (12 ต.ค. 2569)

ได้มาจากการถามตอบแบบ grilling กับผู้ใช้ ตัวเลือกที่ผู้ใช้เลือกอยู่ในคอลัมน์ "ตัดสินใจ"

## ขอบเขตและเทคโนโลยี

| เรื่อง | ตัดสินใจ | เหตุผลและบริบท |
| --- | --- | --- |
| เป้าหมายรอบนี้ | เดโมไปเสนอฝ่ายกิจการนิสิต ไม่ใช่ส่งวิชา | ผู้ใช้: "เอาให้ฟังก์ชันมันใช้ได้ แอพสวย เพื่อไปสาธิตให้เขาก่อน" การคุยรอบแรกไม่เป็นทางการ |
| ระดับความจริงของข้อมูล | ตอนนี้จำลองก่อน แผนคือต่อ Firebase จริง | ตอนแรกเลือก backend จริง (Firebase) แต่รอบสุดท้ายผู้ใช้บอก "ระบบอะไรยังทำไม่ได้จำลองข้อมูลขึ้นมาก่อน" และยังไม่มีบัญชี Firebase/Cloudflare |
| Stack ของเดโม | Web app (PWA) + React | ผู้ใช้: "ใช้อะไรก็ได้ที่ออกมาสวย interactive ดู high-end" PWA ส่งลิงก์เดียวเปิดได้ทุกเครื่องไม่ต้องติดตั้ง ส่วน Flutter ติดตั้งบน iPhone/iPad จาก Windows ไม่ได้ (ต้องมี Mac) |
| Stack วิชา | น่าจะเป็น Flutter ทำทีหลัง | ผู้ใช้ยืนยันว่า Flutter แต่ตอนนี้ยังไม่ต้องทำ |
| ชื่อแอพ | NU Activity Transcript | ผู้ใช้ตั้งเอง |
| Deploy | GitHub Pages บัญชี bvnixx649 | ผู้ใช้บอก "ได้ใช้ github" และอยากได้ลิงก์ที่แชร์ได้ |

## ผู้ใช้และการยืนยันตัวตน

| เรื่อง | ตัดสินใจ | เหตุผลและบริบท |
| --- | --- | --- |
| ผู้ใช้กี่ฝั่ง | นิสิต + ผู้คุมกิจกรรม (ไม่มีหน้าแอดมิน) | ผู้คุม export Excel ไปคีย์ต่อเอง พอสำหรับต้นแบบ |
| บัญชีนิสิต | รหัสนิสิต + PIN 6 หลัก | ครั้งแรกกรอกชื่อ รหัส คณะ ตั้ง PIN เปลี่ยนเครื่องใช้รหัส+PIN กลับเข้าบัญชีเดิม ไม่ใช้ Google Sign-In เพราะ popup มีปัญหาใน PWA บน iPhone และต้อง host บน Firebase Hosting |
| ผู้คุมเข้าระบบ | รหัสหน่วยงานที่ฝ่ายกิจการแจก | ผู้คุมส่วนใหญ่เป็นนิสิตกรรมการชมรม ใครมีรหัสหน่วยงานก็เป็นผู้คุมได้ |
| กันลงชื่อแทนเพื่อน | QR หมุนทุก 10 วินาที + ตรวจ GPS | ถ่ายรูป QR ส่งต่อใช้ไม่ได้ และต้องอยู่ใกล้ผู้คุมจริง ไม่บังคับอีเมล มน. |
| GPS เทียบกับอะไร | มือถือผู้คุมตอนเปิด QR ระยะ 150 ม. | ไม่ต้องปักหมุดตอนสร้างกิจกรรม แม่นแม้ย้ายสถานที่กะทันหัน (บวกค่าคลาดเคลื่อน GPS ได้สูงสุดฝั่งละ 100 ม.) |
