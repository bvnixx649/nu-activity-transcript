# HANDOFF: NU Activity Transcript

อ่านไฟล์นี้ก่อนเริ่มงานในแชทใหม่ บันทึกล่าสุด 12 ต.ค. 2569 (วันแรกของโปรเจค)

ไฟล์อื่นในโฟลเดอร์นี้:
- [DECISIONS.md](DECISIONS.md) การตัดสินใจทั้งหมดพร้อมเหตุผล
- [FEATURES.md](FEATURES.md) รายการฟังก์ชันภาษาไทย (ใช้ทำรายงานหรือสไลด์ได้)
- [ARCHITECTURE.md](ARCHITECTURE.md) โครงสร้างโค้ด ข้อมูล QR และแผนต่อ Firebase

## โปรเจคนี้คืออะไร

แอพเก็บชั่วโมงจิตอาสาและกิจกรรมคณะของนิสิต มหาวิทยาลัยนเรศวร งานกลุ่มวิชา Mobile Application

ปัญหาที่แก้: ฝ่ายที่ดูแลกิจกรรมจิตอาสาประกาศผ่าน Facebook นิสิตเห็นบ้างไม่เห็นบ้าง และผู้คุมต้องคีย์รายชื่อเอง

เป้าหมายตอนนี้ไม่ใช่ส่งวิชา แต่เป็นเดโมไปเสนอฝ่ายกิจการนิสิตก่อน (คุยแบบไม่เป็นทางการ) ต้องฟังก์ชันหลักใช้ได้ สวย interactive ดู high-end ระบบไหนยังทำไม่ได้ให้จำลองข้อมูลไว้ก่อน เวอร์ชันส่งวิชาอาจทำใหม่ด้วย Flutter ทีหลัง

## ทดสอบแล้ว

ทดสอบด้วย headless Chrome ขนาดมือถือ 390x844 และ iPad 820x1180 (สคริปต์อยู่ใน `scripts/e2e/`):
- เดินครบทุกหน้า ไม่มี console error ไม่มี horizontal overflow
- QR ข้ามเครื่องจริง: เครื่องผู้คุมเปิด QR แล้วเครื่องนิสิตสแกนภาพหน้าจอ ผล อยู่ห่าง 40 ม. ได้ชั่วโมง, สแกนซ้ำถูกบล็อก, ห่าง 1,779 ม. ถูกบล็อก, ภาพเก่า 42 วินาทีขึ้น QR หมดอายุ
- light และ dark mode

ยังไม่ได้ทดสอบบนเครื่องจริง: กล้องบน iPhone/Android, เพิ่มลงหน้าจอโฮม, แจ้งเตือนบนหน้าจอล็อก ผู้ใช้ต้องลองเอง

## งานถัดไปที่น่าจะทำ

1. ผู้ใช้ลองบนมือถือจริง 2 เครื่อง แล้วเก็บ feedback หลังไปคุยกับฝ่ายกิจการ
2. ต่อ Firebase (แผนอยู่ใน ARCHITECTURE.md) ผู้ใช้ต้องสร้างโปรเจค Firebase เอง Claude สมัครบัญชีให้ไม่ได้
3. Cloudflare Worker สำหรับส่ง push ข้ามเครื่อง (ผู้ใช้ต้องสมัคร Cloudflare เอง)
4. ระบบเตือนก่อนกิจกรรมเริ่มจริง (ตอนนี้มีแค่สวิตช์กับข้อมูลตัวอย่าง)
5. ถ้าฝ่ายกิจการมีฟอร์ม Excel ที่ใช้อยู่ ปรับคอลัมน์ export ให้ตรง
6. ภายหลัง: เวอร์ชัน Flutter สำหรับส่งวิชา, ให้เพื่อนในกลุ่มเข้ามาแก้โค้ด

## คำถามที่ยังเปิดอยู่

- เกณฑ์ชั่วโมงที่ มน. กำหนด: หาออนไลน์ไม่เจอ ผู้ใช้บอกว่ายังไม่ต้องกำหนด
- ตัวอย่างโพสต์กิจกรรมจริงจาก Facebook และฟอร์ม Excel ของฝ่ายกิจการ: ผู้ใช้บอกว่ายังไม่ต้อง
- การใช้ตรามหาวิทยาลัยตอนใช้งานจริง ต้องขออนุญาตและขอไฟล์ทางการจากงานประชาสัมพันธ์ มน.
- เพื่อนในกลุ่มต้องเข้ามาแก้โค้ดด้วย แต่ยังไม่ได้คุยรายละเอียด

## สิ่งที่ผู้ใช้ชอบและไม่ชอบ (สำคัญ)

- คุยภาษาไทย ศัพท์เทคนิคใช้อังกฤษได้
- เกลียดงานที่ดูเป็น AI slop: ห้ามมี eyebrow (ป้ายตัวเล็กเหนือหัวข้อ), ห้ามกล่อง callout ติดป้าย, ห้าม caption ที่ไม่มีข้อมูล, ห้ามใช้ "·" เป็นตัวคั่น, ห้ามใช้ em-dash
- ชอบงาน high-end interactive แบบ Brilliant, samwho.dev, Luma; whitespace เยอะ; ปุ่มที่กดบ่อยต้องใหญ่
- ใช้ iPad (เปิด Reduce Motion แต่ยังอยากเห็น animation อย่า gate ด้วย prefers-reduced-motion) และมือถือ Android
- ถ้าไม่แน่ใจเรื่องดีไซน์ให้หา reference จริงก่อน ทำ prototype ให้ดูก่อนทำทั้งหมด
- ห่วงเรื่อง token ถ้าเปลี่ยนไปงานใหญ่ชิ้นใหม่ให้แนะนำเปิดแชทใหม่
- ต้องการลิงก์ที่แชร์ให้เพื่อนได้ (GitHub Pages บัญชี bvnixx649)

## วิธีรันและ deploy

```bash
npm install
npm run dev
npm run deploy
```

- `npm run dev` เปิดที่ localhost กล้องและ GPS ใช้ได้บน localhost หรือ https เท่านั้น เปิดผ่าน IP ในวง LAN แบบ http กล้องจะไม่ทำงาน
- `npm run deploy` = `vite build` แล้ว `scripts/deploy.mjs` push โฟลเดอร์ `dist` ไป branch `gh-pages` ด้วย credential ของ GitHub CLI (บัญชี bvnixx649) ใช้แพ็กเกจ `gh-pages` ไม่ได้เพราะมันไปใช้ credential เริ่มต้นของเครื่องซึ่งเป็นอีกบัญชี
- repo นี้ตั้ง credential.helper แบบ local ให้ใช้ gh CLI แล้ว `git push` ปกติใช้ได้เลย
- Pages อัปเดตประมาณ 1 นาทีหลัง deploy

ทดสอบ headless (ต้องรัน `npx vite preview --port 4173` ก่อน):

```bash
python -I scripts/e2e/walk.py <โฟลเดอร์เก็บภาพ>
```

- `walk.py` เดินทุกหน้าแล้วถ่ายภาพ 20 จอ
- `qrflow.py` ทดสอบ QR ข้ามเครื่อง (ใกล้ ไกล ซ้ำ หมดอายุ) ใช้เวลาราว 1 นาที
- `check2.py` light/dark และ Transcript
- `live.py` เช็คเว็บที่ deploy แล้วบนขนาดมือถือและ iPad
